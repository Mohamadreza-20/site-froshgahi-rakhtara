# Rakhtara | فروشگاه اینترنتی پوشاک

Rakhtara یک فروشگاه اینترنتی فارسی و راست‌چین است که با React و Vite ساخته شده و در کنار تجربه خرید، یک پنل مدیریت برای کنترل محصولات، کاربران، دسته‌بندی‌ها، نظرات و اسلایدهای صفحه اصلی دارد.

این پروژه به‌عنوان نمونه‌کار Frontend طراحی شده و روی کیفیت رابط کاربری، مدیریت داده، فرم‌ها، سبد خرید، دسترسی‌پذیری، SEO و بهینه‌سازی عملکرد تمرکز دارد.

> **نوع پروژه:** Frontend Portfolio / Demo  
> **API:** JSON Server  
> **رابط کاربری:** فارسی و RTL  
> **دسته‌بندی‌ها و اطلاعات فروشگاه:** `server-data/db.json`

---

## پیش‌نمایش و مسیرهای اصلی

پس از اجرای پروژه، این مسیرها در دسترس هستند:

| مسیر | توضیح |
|---|---|
| `/` | صفحه اصلی فروشگاه |
| `/products` | فهرست محصولات، جست‌وجو، فیلتر و مرتب‌سازی |
| `/category/:id` | صفحه محصولات یک دسته‌بندی |
| `/product/:id` | جزئیات محصول و مدیریت تعداد خرید |
| `/account` | پنل حساب کاربری |
| `/auth` | ورود و ثبت‌نام |
| `/dashboard/home` | داشبورد مدیریت |
| `/dashboard/products` | مدیریت محصولات |
| `/dashboard/categories` | مدیریت دسته‌بندی‌ها |
| `/dashboard/users` | مدیریت کاربران |
| `/dashboard/comments` | مدیریت نظرات |

برای مشاهده پروژه به‌صورت محلی، بعد از اجرای سرور Frontend آدرس زیر را باز کنید:

```text
http://localhost:5173
```

JSON Server نیز روی این آدرس اجرا می‌شود:

```text
http://localhost:3000
```

### مدیریت دسته‌بندی‌ها

دسته‌بندی‌ها از `server-data/db.json` خوانده می‌شوند و منبع مشترک بخش‌های مختلف فروشگاه هستند. در CMS می‌توان دسته‌بندی را اضافه، ویرایش و حذف کرد.

هنگام تغییر نام دسته‌بندی، ارتباط محصولات همان دسته نیز به‌روزرسانی می‌شود. تعداد محصولات در صفحه اصلی، صفحه محصولات و صفحه دسته‌بندی از داده واقعی محصولات محاسبه می‌شود.

## جست‌وجو و فیلتر

برای جلوگیری از ارسال درخواست در هر تغییر کوچک Input، جست‌وجوی محصولات و کاربران با Debounce انجام می‌شود.

در صفحه محصولات فیلترهای دستی نیز با Debounce اعمال می‌شوند، از جمله:

- حداقل قیمت
- حداکثر قیمت
- وضعیت موجودی
- دسته‌بندی
- جست‌وجوی متنی

پس از تغییر فیلتر یا جست‌وجو، صفحه‌بندی دوباره از صفحه اول محاسبه می‌شود و Focus ورودی حفظ می‌شود.

## سبد خرید و موجودی

موجودی محصول در تمام مسیرهای اصلی کنترل می‌شود:

- صفحه جزئیات محصول
- کارت محصول
- سبد خرید
- Merge سبد مهمان و کاربر

مثلاً اگر موجودی محصول ۱۵ عدد باشد و ۳ عدد در سبد قرار گرفته باشد، فقط ۱۲ عدد دیگر قابل افزودن است. اگر تعداد درخواستی بیشتر از موجودی باقی‌مانده باشد، عملیات به‌صورت کامل رد می‌شود و مقدار ناقص به سبد اضافه نمی‌شود.

## SEO

پروژه به‌صورت Vite SPA اجرا می‌شود و در زمان Build اطلاعات SEO برای صفحات عمومی تولید می‌شوند.

موارد اصلی SEO:

- Title و Description
- Canonical URL
- Open Graph
- Twitter metadata
- JSON-LD برای محصولات
- Sitemap
- Robots
- داده اولیه برای prerender

این ساختار جایگزین SSR کامل یک فریم‌ورک سرورمحور نیست و پروژه عمداً با Vite نگهداری شده است.

## محدودیت‌های JSON Server

JSON Server در این پروژه نقش Backend واقعی را ندارد و فقط برای شبیه‌سازی API در نمونه‌کار استفاده می‌شود.

### تصاویر

آپلود و ذخیره‌سازی واقعی فایل تصویر روی سرور پشتیبانی نمی‌شود. برای Showcase و تصاویر محصولات باید از یکی از این روش‌ها استفاده شود:

1. قرار دادن تصویر در `public`
2. استفاده از یک URL معتبر و قابل دسترس

برای Production بهتر است فایل‌ها روی Object Storage یا سرویس مدیریت رسانه ذخیره شوند و Backend فقط URL و metadata فایل را نگهداری کند.

### احراز هویت

احراز هویت این پروژه برای محیط Demo و Portfolio طراحی شده است. JSON Server و state سمت کلاینت جایگزین سیستم احراز هویت امن و Backend واقعی نیستند.

## متغیرهای محیطی

برای اجرای معمول پروژه، اگر `VITE_API_URL` تنظیم نشود، API به‌صورت پیش‌فرض از `http://localhost:3000` استفاده می‌کند.

نمونه متغیرها در `.env.example` قرار دارد:

```env
VITE_API_URL=http://localhost:3000
VITE_SITE_URL=http://localhost:5173
VITE_SEO_API_URL=http://localhost:3000
VITE_SEO_STRICT=true
```

در صورت نیاز:

```bash
copy .env.example .env.local
```

در Linux و macOS:

```bash
cp .env.example .env.local
```

## استقرار

پروژه برای استقرار به‌صورت SPA آماده شده و rewrite مسیرها به `index.html` در تنظیمات deployment در نظر گرفته شده است.

برای انتشار روی سرویس‌هایی مانند Netlify یا Vercel:

1. پروژه را روی GitHub قرار دهید.
2. Repository را به سرویس موردنظر متصل کنید.
3. متغیرهای محیطی را تنظیم کنید.
4. Build Command را روی یکی از اسکریپت‌های Build پروژه قرار دهید.
5. برای Backend واقعی، JSON Server را با یک API واقعی جایگزین کنید.
